Contributing to FastSprout

Use Python 3.12, 3.13, or 3.14 and uv. Run commands from the repository root.

Set up the development environment and Git hooks:

    uv sync --locked --all-extras --all-groups
    uv run prek install

Read src/AGENTS.md and the nested AGENTS.md files for the code you change.
Tests belong under src/tests/, following the source package structure.
Reuse existing fixtures and test classes. Include typing cases for public API
changes; the typing tests run both mypy and basedpyright.

Run the checks before submitting:

    uv run prek run --all-files
    uv run pytest

The configured requirements are 100% test coverage and 100% public API type
completeness. Run tests with the supported Python versions when changing
version-sensitive behavior. Report failing checks in your pull request;
do not lower thresholds or add suppressions to hide failures.

Runnable examples live in examples/. After changing an example, regenerate
its documentation and check the site:

    uv run --all-extras --group docs python scripts/generate_readme_docs.py
    uv run --all-extras --group docs mkdocs build --strict

The generator runs examples and captures their output. Update the Python
source rather than editing generated pages under docs/learn/examples/.

Submit a pull request against development. Keep each commit focused on one
complete change, including its tests, examples, and documentation. Explain
the behavior changed and the checks you ran.

CHANGELOG.txt is generated from Git history by the changelog CI job.
Do not edit entries manually. Use descriptive commit subjects with the layer
as their scope, for example feat(actions): add a service operation. Entries
are grouped by layer, then Features, Fixes, or Changes. To preview locally:

    uv tool run --from git-cliff==2.14.2 git-cliff --config cliff.toml --output CHANGELOG.txt

For security reports, follow SECURITY.md instead of opening a public issue
with vulnerability details. Contributions use the repository's Apache-2.0
license; see LICENSE.
